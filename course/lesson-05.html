01
Новые термины урока
📖 Теоретический блок — смотрим вместе с видеоуроком. Здесь собраны все ключевые понятия урока 5. Возвращайтесь к ним в любой момент.
n8n (читается «н-эйт-н», от «nodemation»)
Платформа для визуального создания автоматизаций. Вы собираете процессы из блоков-нод (триггер → действие → действие), без написания кода.
📌 «Когда приходит письмо с темой "Счёт" → сохрани вложение на Google Drive → добавь строку в Google Sheets → напиши мне в Telegram». Этот сценарий в n8n собирается за 10 минут мышкой.
Workflow (воркфлоу)
Один цельный сценарий автоматизации в n8n. Состоит из триггера и последовательности нод.
📌 «Workflow: Напоминание о встрече за 1 час» — один воркфлоу. «Workflow: Запись платежа в таблицу» — другой воркфлоу. Они могут работать независимо или вызывать друг друга.
Node (нода, узел)
Один блок внутри workflow — одно действие или одно соединение с сервисом. Бывает нодой-триггером (старт) или нодой-действием (шаг).
📌 Нода Google Calendar: Create Event создаёт событие. Нода Gmail: Send отправляет письмо. Нода If проверяет условие.
Trigger (триггер)
Событие, которое запускает workflow. Именно оно «нажимает кнопку старт».
📌 Триггеры в n8n — «каждый день в 9:00» (cron), «когда приходит webhook по URL», «когда в календаре появляется новое событие», «когда в папке Drive появляется файл».
Webhook (вебхук)
URL-адрес, при обращении к которому запускается workflow. Идеальный способ связать OpenClaw с n8n.
📌 n8n даёт вам URL вида https://n8n.ваш-домен.com/webhook/abc123. OpenClaw делает POST на этот URL — и workflow в n8n запускается с теми данными, что агент отправил.
OAuth 2.0
Стандартный протокол, которым вы разрешаете одному сервису (n8n, OpenClaw) действовать от вашего имени в другом сервисе (Google). Без передачи пароля.
📌 Когда вы нажимаете «Войти через Google» — это и есть OAuth. Вы разрешаете приложению доступ к определённым данным, и оно получает «токен» вместо пароля.
Client ID + Client Secret
Два «ключа», которые Google выдаёт вашему проекту в Cloud Console. Их нужно вставить в n8n и в OpenClaw, чтобы они могли запросить OAuth-разрешение.
📌 Client ID = «логин» вашего приложения. Client Secret = «пароль» вашего приложения. Оба публикуются в своих конфигурациях — Google узнаёт «ага, это тот самый проект Стаса».
Access Token + Refresh Token
После OAuth-входа Google выдаёт два токена. Access — короткоживущий (час), используется для запросов. Refresh — долгоживущий, им обновляют Access. В режиме Testing refresh живёт 7 дней → потом всё ломается.
📌 Это важно! Подробно про 7 дней — в секции 06, часть 3.
Google Cloud Console
Админка Google, где вы создаёте «проекты», включаете в них нужные API и получаете Client ID/Secret.
📌 console.cloud.google.com — наш «рабочий кабинет» для подключения Google-сервисов к n8n и OpenClaw.
Cron / Cron Job
Задача по расписанию. Синтаксис: 5 звёздочек (минуты часы день-месяца месяц день-недели). OpenClaw умеет запускать Cron Jobs внутри себя, без n8n.
📌 0 9 * * * = каждый день в 9:00. 0 18 * * 5 = каждую пятницу в 18:00. */30 * * * * = каждые 30 минут.
TOTP (2FA)
Одноразовый шестизначный код, который меняется каждые 30 секунд в приложении-аутентификаторе. Стандарт двухфакторной аутентификации.
📌 Вводите пароль + код из Google Authenticator. Даже если пароль украли — без вашего телефона не войдут.
API
(Из урока 2) Способ, которым программы общаются. n8n общается с Google через Google API. OpenClaw общается с n8n через API n8n.
📌 Вспомните ресторан из урока 2: n8n — новый официант, который умеет носить заказы между десятком кухонь.

Архитектура: как n8n встраивается в систему
🗺️ Эту схему надо понять — от неё зависит всё дальнейшее. К концу урока все эти стрелки у вас реально заработают.
Вы (идея, голос, текст) ↓ ┌───────────────────┐ │ Telegram-бот │ ← Домен не нужен └─────────┬─────────┘ ↓ ┌───────────────────┐ │ OpenClaw (VPS) │ │ «ИИ-директор» │ └─────────┬─────────┘ ↓ ┌───────────────┼──────────────┬──────────────┐ ↓ ↓ ↓ ↓ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ Cron Jobs│ │ n8n │ │ GitHub │ │ Google │ │(OpenClaw)│ │(Домен №2)│ │(Домен №1)│ │ (API) │ └──────────┘ └─────┬────┘ └──────────┘ └──────────┘ ↓ ┌───────────────────┐ │ Google API │ │ (Calendar, Drive, │ │ Sheets, Gmail) │ └───────────────────┘

Что делает что:

— OpenClaw — мозг. Принимает запрос, решает что делать, вызывает инструменты.
— Cron Jobs внутри OpenClaw — простые задачи агента по расписанию (напомнить, написать дайджест, проверить календарь). Без внешних инструментов.
— n8n — отдельная платформа для сложных многоступенчатых автоматизаций между сервисами. Живёт на отдельном домене.
— GitHub + Домен №1 — публичные сайты и лендинги (из урока 4).
— Google API — календарь, диск, таблицы, почта. Подключаются и к n8n, и к OpenClaw.

Когда использовать n8n vs Cron Jobs в OpenClaw:

ЗадачаГде делаемПочему
«Напомни мне каждое утро про встречи дня»Cron JobsПростая задача, агент справляется сам
«Новое событие → SMS клиенту + папка Drive + строка в Sheets»n8nМногоступенчатый процесс с несколькими сервисами
«Каждую пятницу в 18:00 — сводка недели»Cron JobsАгент берёт данные и пишет текст
«Платёж → CRM + чек в Drive + благодарственное письмо»n8nРазные сервисы, сложная логика
«Раз в час — Gmail с "срочно" → сообщи»n8nТам удобнее триггеры на входящее письмо
💡 Правило: простое — делаем в OpenClaw через Cron Jobs. Сложное или многосервисное — в n8n.

Часть 4: Подключение Claude Code к n8n через MCP
🧠 MCP (Model Context Protocol) — стандарт, которым Claude Code общается с внешними сервисами. Подключив MCP-сервер n8n, вы даёте Claude Code глубокое понимание всех 535+ нод n8n — он перестанет галлюцинировать имена полей и начнёт собирать рабочие workflow с первой попытки.

Есть два MCP-сервера для n8n:

— Официальный от n8n GmbH — встроен во все версии n8n (нужна 2.18.4+). Умеет искать, смотреть детали и запускать workflow, а после обновления весной 2026 — ещё и создавать и править workflow с нуля прямо в вашем n8n по текстовому запросу. Подключается в Claude Desktop одним кликом через Connectors → Directory → n8n. Как подключить — офиц. документация n8n MCP.

— Community-пакет n8n-mcp от Czlonkowski — даёт Claude Code полную документацию по всем нодам, умеет валидировать и создавать workflow с нуля. С ним вайб-кодинг автоматизаций в Claude Code работает заметно лучше.

Что выбрать — решаете вы. Оба варианта рабочие и делают похожие вещи: официальный проще подключить и теперь тоже умеет собирать workflow, community-пакет глубже заточен под вайб-кодинг в Claude Code. Как работать и какой MCP использовать — на ваше усмотрение. Дальше в уроке показываем на примере community-пакета.

🔄 У OpenClaw и n8n разные сильные стороны. В этой секции настроим две отдельные вещи: (1) OpenClaw будет отправлять данные в n8n через webhook, (2) n8n будет присылать вам уведомления в Telegram напрямую, минуя OpenClaw.

Разбираемся на пальцах:

1. OpenClaw → n8n. Вы говорите агенту: «запиши платёж 50 тысяч». OpenClaw понимает, что вы сказали, и отправляет данные на специальный URL в n8n (webhook). n8n получает данные и делает свою работу — например, пишет строку в Google-таблицу. Telegram-бот в этой цепочке — только канал связи между вами и OpenClaw. С n8n бот не общается.

2. n8n → вы (в Telegram). n8n сам пишет вам сообщение в Telegram, используя токен того же бота. OpenClaw это сообщение не видит и не обрабатывает — n8n просто использует Telegram Bot API, чтобы написать вам напрямую. Полезно, когда нужно уведомление от n8n не гоняя сообщение через агента.

⚠️ Конфликта нет. OpenClaw слушает ваши входящие сообщения. n8n только отправляет исходящие. Это разные функции Telegram Bot API — они друг другу не мешают.

Часть 2: Базовый синтаксис Cron
* * * * * │ │ │ │ │ │ │ │ │ └── день недели (0-7, 0 и 7 = воскресенье) │ │ │ └─────── месяц (1-12) │ │ └──────────── день месяца (1-31) │ └───────────────── час (0-23) └────────────────────── минута (0-59)

Примеры:

— 0 9 * * * — каждый день в 9:00
— 30 8 * * 1-5 — каждый будний день в 8:30
— 0 18 * * 5 — каждую пятницу в 18:00
— 0 10 1 * * — 1-го числа каждого месяца в 10:00
— */30 * * * * — каждые 30 минут
— 0 */2 * * * — каждые 2 часа (в 00:00, 02:00, 04:00...)

⚠️ Важно: Cron по умолчанию работает по таймзоне сервера (чаще UTC). Убедитесь, что агент знает ваш часовой пояс. В Cron OpenClaw обычно можно указать TZ в самом правиле.

📦 Как импортировать workflow в свой n8n (5 шагов)

1. Скачайте нужный JSON-файл с Google Drive по ссылке выше.

2. Откройте свой n8n → Workflows → кнопка ⋯ в правом верхнем углу → Import from File.

3. Выберите скачанный JSON — n8n откроет workflow в редакторе.

4. Подставьте свои значения вместо плейсхолдеров:

— <ВАШ_EMAIL>, <ВАШЕ_ИМЯ>, <ВАШ_TELEGRAM_USER_ID> — личные данные
— <OPENAI_CREDENTIAL_ID>, <GOOGLE_SHEETS_CREDENTIAL_ID>, <GOOGLE_CALENDAR_CREDENTIAL_ID>, <GMAIL_CREDENTIAL_ID>, <TELEGRAM_CREDENTIAL_ID>, <SERPAPI_CREDENTIAL_ID> — в каждой ноде выбрать свой credential из выпадающего списка (создаются через Settings → Credentials)
— <FINANCE_SHEET_ID>, <CONTACTS_SHEET_ID> — ID ваших Google Sheets таблиц (берётся из URL таблицы: docs.google.com/spreadsheets/d/<ТУТ_ID>/edit)
— <EMAIL_WORKFLOW_ID>, <CONTACTS_WORKFLOW_ID>, <CALENDAR_WORKFLOW_ID>, <FINANCEANALYST_WORKFLOW_ID>, <FINANCELOGGER_WORKFLOW_ID> — только в MAIN — это ссылки на другие ваши workflow, их ID возьмёте после импорта остальных пяти
— <EXCHANGERATE_API_KEY> — только в FINANCE LOGGER — получите бесплатный ключ на exchangerate-api.com, бесплатный тариф полностью хватает

Что за <OPENAI_CREDENTIAL_ID> и зачем он нужен: OpenAI здесь — это «мозг» AI-агентов внутри workflow: языковая модель, которая понимает ваши сообщения, извлекает суммы, имена и категории, формулирует ответы. Чтобы эти workflow заработали, нужен ваш API-ключ OpenAI — создаётся в platform.openai.com, а затем в n8n добавляется как OpenAI credential через Settings → Credentials. Если предпочитаете другого провайдера — можно подключить свой ключ через OpenRouter, логика workflow при этом не меняется.

5. Активируйте workflow переключателем в правом верхнем углу.

⚠️ Импортируйте в таком порядке: сначала CALENDAR, CONTACTS, EMAIL, FINANCE LOGGER, FINANCE ANALYST — они независимы. Последним — MAIN: в нём нужно прописать workflow ID предыдущих пяти (возьмёте их из URL каждого импортированного workflow вида /workflow/<ID>).
