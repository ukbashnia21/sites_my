````text
— Проверку, что подключение работает без пароля.
— Базовый hardening сервера (опционально, но желательно): отключить парольный вход в /etc/ssh/sshd_config, чтобы сервер нельзя было брутфорсить — со страховкой «второй открытый терминал на случай, если что-то пойдёт не так».

— Объясняй каждый шаг простыми словами — что мы делаем и зачем.
````

## L03-PROMPT-011 — 📋 Рекомендации по SOUL.md — скопировать и отправить в Claude Code

Урок 3 · Раздел 11 — Настройка личности агента — SOUL.md и USER.md

````text
Анатомия идеального файла SOUL.md для AI-агентов.

SOUL.md — это единственный файл, который вы пишете для AI-агента самостоятельно. Он находится в самом начале системного промпта: до памяти, до скиллов и до инструментов. Именно он определяет, кем является агент, когда начинает работу. Час, потраченный на этот файл, влияет на каждое последующее взаимодействие.

Вот 8 разделов, которые имеют значение:

→ identity — одно предложение о том, кто агент, а не что он делает
→ core truths — базовые принципы в повелительной форме, каждый с кратким пояснением в одну строку
→ worldview — выраженные взгляды по разным областям, достаточно конкретные, чтобы по ним можно было предсказать поведение агента
→ voice — конкретные правила общения агента, а не набор прилагательных
→ expertise — основная область компетенции, инструменты, которыми агент владеет свободно, и ситуации, где он передаёт задачу другому специалисту
→ boundaries — явные ограничения и вещи, которые агент делать не будет, без расплывчатых формулировок
→ memory policy — правила того, что сохраняется в памяти, а что остаётся приватным
→ pet peeves — фразы, речевые обороты и тон общения, которые агент никогда не использует

Большинство пишут что-то вроде «будь полезным и профессиональным» — и на этом заканчивают. Это ничего не меняет: любая модель и так старается быть полезной. Агенты, которые реально становятся лучше со временем, имеют SOUL.md с настоящими взглядами, ограничениями и стилем общения — который можно предсказать ещё до прочтения ответа.

Хороший SOUL.md обычно занимает от 30 до 80 строк. Конкретика важнее полноты охвата.
````

## L03-PROMPT-013 — 📋 Промпт: установить показ лимитов (в Claude Code)

````text
Ты — DevOps-инженер. Установи на мой сервер с OpenClaw механизм, который к каждому ответу бота в Telegram дописывает строку с остатком лимитов Codex (5-часовое окно и недельное). Всё нужное лежит в папке openclaw-codex-footer/ в этом проекте.

Работай аккуратно: сначала обследуй сервер, потом меняй. Не угадывай пути, имена сервисов и команды — проверяй на реальном сервере. Не трогай другие сервисы.

Что в папке:
- scripts/openclaw-usage-writer.sh — хостовый скрипт: раз в минуту читает лимиты (openclaw models status) и пишет их в файл gpt-usage.txt в workspace агента. Файл перезаписывается целиком — не растёт.
- plugin/codex-usage-footer/ — плагин OpenClaw: на хуке message_sending дописывает содержимое файла к исходящим сообщениям Telegram. Без участия модели, идемпотентно.
- README.md — описание и ручная инструкция.

Сделай по шагам; перед каждым шагом одной фразой говори, что делаешь:
1. Прочитай openclaw-codex-footer/README.md целиком.
2. Обследуй мою установку OpenClaw (проверь командами, не угадывай): убедись, что CLI доступен (openclaw --version, openclaw doctor); найди каталог данных OpenClaw (обычно ~/.openclaw) и папку workspace агента; имя systemd-сервиса gateway (обычно openclaw-gateway — проверь: systemctl status openclaw-gateway). Если установка нестандартная (например, в Docker-контейнере) — остановись и спроси меня.
3. Впиши найденные значения в шапку scripts/openclaw-usage-writer.sh (OPENCLAW_DIR, GW_SERVICE, DATA_DIR).
4. Поставь writer: скопируй в /opt/openclaw-ops/, chmod 755, запусти один раз и проверь cat <DATA_DIR>/workspace/gpt-usage.txt (ожидаемо строка вида 5ч NN% · ⏱ … | неделя NN% · ⏱ …).

   openclaw config set plugins.load.paths '["<DATA_DIR>/plugins"]' --strict-json
   openclaw config set plugins.entries.codex-usage-footer.enabled true --strict-json
   openclaw config validate
   перезапусти gateway: openclaw gateway restart
6. Добавь строку в хостовый crontab — ТОЛЬКО добавлением, не затирая существующие: * * * * * /opt/openclaw-ops/openclaw-usage-writer.sh >/dev/null 2>&1
7. Проверь: openclaw plugins list | grep codex-usage-footer → должен быть enabled. Затем напиши боту любое сообщение — внизу ответа должна появиться строка с лимитами.
8. Короткий отчёт: что куда поставлено и что проверено.

Правила: не угадывай — что не подтверждено инспекцией сервера, не используй; не хватает данных — спроси; crontab меняй только добавлением; секреты в скрипты не вписывай; показывай реальный вывод команд; другие сервисы на сервере не трогай.
````

## L06-PROMPT-022 — 📋 Промпт Claude Code-боту (🛠️ инженерный) — клон vault для OpenClaw + chown

Урок 6 · ЧАСТЬ 2 · ГЛАВА 02 · Раздел 54 — Шаг 2. Готовим vault для OpenClaw-агента

````text
Ключ добавлен в GitHub. Делай по плану «Путь A+ через chown root:root»:

1. Проверь связь с GitHub под новым ключом:
   ssh -T -i ~/.ssh/github_deploy_openclaw_main \
       -o IdentitiesOnly=yes git@github.com
   (должен ответить "Hi <username>/second-brain!")

2. Склонируй vault в /root/.openclaw/obsidian-vault/ через GIT_SSH_COMMAND:
   GIT_SSH_COMMAND="ssh -i ~/.ssh/github_deploy_openclaw_main \
       -o IdentitiesOnly=yes" \
   git clone git@github.com:<твой-username>/second-brain.git \
       /root/.openclaw/obsidian-vault/

3. Зашей core.sshCommand в локальный config клона:
   cd /root/.openclaw/obsidian-vault && \
   git config core.sshCommand \
       "ssh -i /home/<user>/.ssh/github_deploy_openclaw_main -o IdentitiesOnly=yes"
   (используй ПОЛНЫЙ путь к ключу, не ~ — потому что после chown
   репо будет работать под root, а у root другой $HOME)

4. Настрой git identity для коммитов от агента:
   git config user.name "openclaw-main" && \
   git config user.email "openclaw-main@server"

5. ⭐ КРИТИЧЕСКИЙ ШАГ — chown на root (без него скилл OpenClaw
   упадёт на первом же git pull с "dubious ownership"):

   sudo chown -R root:root /root/.openclaw/obsidian-vault

   Если sudo требует пароль и у тебя нет TTY — СТОП, не продолжай.
   Скажи мне честно: "sudo требует пароль, нужен ручной chown
   через VS Code Remote-SSH под root". Я сам сделаю и вернусь.

6. После chown сделай ACL чтобы root мог читать SSH-ключ stas'а
   (без этого ssh упадёт с Permission denied):

   sudo setfacl -m u:root:r ~/.ssh/github_deploy_openclaw_main && \
   sudo setfacl -m u:root:rx ~/.ssh

7. Добавь GitHub fingerprint в known_hosts root'а (без этого
   первый ssh от root упадёт с "Host key verification failed"):
````
