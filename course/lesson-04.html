01
Новые термины урока
📖 Теоретический блок — смотрим вместе с видеоуроком. Ключевые понятия, к которым можно вернуться в любой момент.
GitHub
Онлайн-платформа для хранения кода и файлов с версионированием. Каждое изменение сохраняется в истории — можно откатить, сравнить, работать в команде.
📌 Мы используем GitHub как бесплатный хостинг для сайтов и лендингов. OpenClaw подключается к нему и сам заливает файлы.
Репозиторий (Repository / Repo)
Папка проекта на GitHub. Внутри лежат файлы сайта: HTML, CSS, картинки. Бывает Public (открытый, код виден всем) и Private (закрытый, код видите только вы).
📌 Как папка на вашем компьютере, но в облаке. С историей всех изменений и возможностью работать откуда угодно.
GitHub Pages
Бесплатный хостинг от GitHub. Превращает файлы из репозитория в рабочий сайт с адресом username.github.io или на вашем домене.
📌 Положили index.html в репозиторий → включили Pages → сайт доступен всему миру. Бесплатно.
SSH-ключ
Цифровой пропуск для безопасного подключения к GitHub без логина и пароля. Приватный ключ хранится на сервере (никому не показываем), публичный — добавляем в GitHub.
📌 Как электронный пропуск на работу. Вместо того чтобы каждый раз показывать паспорт (логин/пароль), просто прикладываете карту (SSH-ключ).
Домен
Адрес сайта в интернете (например, mybusiness.com). Покупается у регистратора, принадлежит вам.
📌 Как номер телефона: вы его покупаете, он только ваш, и люди по нему находят именно вас.
DNS (Domain Name System)
Система, которая связывает ваш домен с конкретным сервером. Когда человек вводит mybusiness.com, DNS говорит браузеру: «иди на сервер GitHub Pages».
📌 Как телефонная книга интернета. Вы помните имя (домен), а DNS знает номер (IP-адрес сервера).
DNS-записи (A и CNAME)
A-запись — связывает домен с IP-адресом. CNAME-запись — связывает поддомен (например, www) с другим адресом.
📌 A-запись: «mybusiness.com → 185.199.108.153». CNAME: «www.mybusiness.com → username.github.io».
HTTPS / SSL-сертификат
Шифрование между браузером и сайтом. Замочек 🔒 в адресной строке. GitHub Pages выпускает бесплатный сертификат Let's Encrypt автоматически.
📌 Без HTTPS браузер покажет «Небезопасно». С HTTPS — ваш сайт выглядит профессионально и данные защищены.
Git push
Команда, которая отправляет файлы из локальной папки (или с VPS) в репозиторий на GitHub. OpenClaw делает это автоматически.
📌 «Push» = «толкнуть» файлы из вашего сервера на GitHub. Сайт обновляется через несколько секунд после push.
GitHub MCP
Официальный MCP-сервер от GitHub (помните MCP из урока 3 — «переходник» к внешнему сервису). Даёт Claude Code и агенту OpenClaw готовые структурные инструменты для работы с GitHub: issues, pull requests, ревью кода, поиск по репозиториям.
📌 SSH-ключ умеет пушить файлы, GitHub CLI — создавать репозитории. GitHub MCP добавляет третий слой: агент «видит» ваш GitHub структурно и работает с ним как с набором инструментов.
Скиллы (Skills)
Плагины для Claude Code и OpenClaw. Файл SKILL.md с инструкциями, который учит агента делать конкретную вещь: создавать красивые сайты, работать с API, анализировать данные.
📌 В уроке 3 мы ставили 4 инструмента (плагин Superpowers + 3 MCP: TaskMaster, Playwright, AgentMemory). Сейчас добавим дизайн-скилл frontend-design (через Claude Code) и библиотеку стилей Refero.
ClawHub
Официальный маркетплейс скиллов OpenClaw. Более 13 700 скиллов от сообщества — для дизайна, кода, API, аналитики и многого другого.
📌 Как App Store, но для скиллов вашего AI-агента. Нашли нужный → установили одной командой → агент умеет новое.
02
Как GitHub связан с OpenClaw — схема
🗺️ Весь урок — это построение вот этой цепочки. К концу у вас будет рабочий pipeline: сказали боту → получили сайт на своём домене.
Вы (идея) → Claude / Claude Code (генерирует HTML) ↓ OpenClaw на вашем VPS ↓ Git push по SSH → GitHub (репозиторий) ↓ GitHub Pages (хостинг) ↓ Ваш домен (Porkbun) → Сайт онлайн

В одном предложении: вы пишете боту в Telegram — он создаёт сайт — заливает на GitHub — сайт появляется на вашем домене. Всё автоматически, без единой строчки кода руками.

Регистрация на GitHub и создание репозиториев
💡 Зачем нам GitHub: бесплатный хостинг для сайтов, OpenClaw подключается и сам заливает файлы, каждое изменение сохраняется в истории — можно откатить.
Зарегистрироваться на GitHub
Email + username + пароль. Рекомендация: тот же Gmail, что заводили в уроке 1.
github.com — регистрация
Создать Public-репозиторий (основной)
Кнопка «New repository» → название: например, sites → тип: Public → галочка «Add a README file».
Это наш основной репозиторий для сайтов — именно к нему привяжем домен. Всё бесплатно.
Создать Private-репозиторий (демонстрация)
Создаём ещё один репозиторий с типом Private — код не виден другим пользователям. Полезен для конфиденциальных проектов.
⚠️ GitHub Pages для Private-репозиториев требует GitHub Pro ($4/мес). Для наших целей (лендинги, сайты-визитки) Private не нужен — сам сайт всё равно публичный, HTML-код можно увидеть через DevTools в браузере. Мы будем работать с Public-репозиторием.
04
Подключение к GitHub: SSH, GitHub CLI и MCP
🔑 Настраиваем два инструмента: SSH-ключ — чтобы OpenClaw мог пушить файлы в репозитории. GitHub CLI + токен — чтобы OpenClaw мог сам создавать новые репозитории, управлять настройками и включать GitHub Pages. Вместе они дают полный контроль над GitHub прямо из Telegram.

Что сможет OpenClaw после настройки:

— Клонировать, пушить, коммитить, откатывать изменения (SSH)
— Создавать и удалять репозитории (GitHub CLI)
— Включать и настраивать GitHub Pages (GitHub CLI)
— Создавать ветки, issues, pull requests (GitHub CLI)

Часть 1: SSH-ключ

Шаг 0. Подключиться к VPS — все команды ниже выполняются на сервере, а не на вашем компьютере.

🍎 Подключение к VPS с macOS

Откройте Терминал (Finder → Программы → Утилиты → Терминал) и выполните:

ssh root@<ВАШ_IP_СЕРВЕРА>

Введите пароль от сервера. Вы на VPS.

🪟 Подключение к VPS с Windows

Нажмите Win + X → выберите «Терминал» или «PowerShell» и выполните:

ssh root@<ВАШ_IP_СЕРВЕРА>

Введите пароль от сервера. Вы на VPS.

Если команда ssh не найдена: Windows 10/11 имеет встроенный SSH-клиент, но он может быть отключён. Включите: Параметры → Приложения → Дополнительные компоненты → Добавить компонент → OpenSSH Client.

Сгенерировать SSH-ключ на VPS
Уже подключились к серверу? Выполните команду (одинаковая для всех — это Linux на VPS):
ssh-keygen -t ed25519 -C "ваш-email@gmail.com"
Нажимайте Enter на все вопросы (место хранения — по умолчанию, пароль — можно пустой).
Скопировать публичный ключ
cat ~/.ssh/id_ed25519.pub
Скопируйте всю строку целиком, которая выводится. Она начинается с ssh-ed25519 и заканчивается вашим email.
Добавить SSH-ключ в GitHub
1. Откройте GitHub → иконка профиля → Settings
2. В левом меню: SSH and GPG keys
3. Нажмите New SSH key
4. Title: например, OpenClaw VPS
5. Key type: Authentication Key
6. Key: вставьте скопированную строку
7. Нажмите Add SSH key
github.com/settings/keys — страница SSH-ключей
Проверить SSH-подключение
Вернитесь в терминал VPS и выполните:
ssh -T git@github.com
Если спросит «Are you sure you want to continue connecting?» — напишите yes.
Должно ответить: «Hi username! You've successfully authenticated»
✅ SSH настроен! OpenClaw теперь может клонировать репозитории, пушить файлы, коммитить и откатывать изменения. Переходим к GitHub CLI — он даст возможность создавать новые репозитории.
Часть 2: GitHub CLI + токен
💡 Зачем это нужно: SSH-ключ позволяет работать с файлами внутри существующих репозиториев, но не умеет создавать новые репозитории — это ограничение протокола Git. Для создания репозиториев, управления Pages и других операций с GitHub нужен GitHub CLI — официальная утилита от GitHub, которая работает через API.

Шаг 1. Создать Personal Access Token (PAT) — это «пароль» для GitHub API. Создаётся на сайте GitHub, используется один раз при настройке.

Создать Personal Access Token на GitHub
1. Откройте ссылку ниже (или: GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic))
2. Нажмите Generate new token → Generate new token (classic)
3. GitHub попросит подтвердить пароль
4. Заполните:
   • Note: OpenClaw VPS (название для себя)
   • Expiration: No expiration (или 90 дней — тогда придётся обновлять)
   • Scopes: поставьте галочки на repo (полный доступ к репозиториям) и delete_repo (удаление репо)
5. Нажмите Generate token
6. Скопируйте токен! Он начинается с ghp_ и показывается только один раз. Сохраните его в надёжное место.
github.com/settings/tokens — страница токенов
⚠️ Токен показывается только один раз! Если не скопировали — придётся создавать новый. Сохраните его в заметки или менеджер паролей.

Шаг 2. Установить GitHub CLI на VPS — все команды выполняются на сервере (вы уже подключены по SSH).

Установить GitHub CLI на VPS
Скопируйте и вставьте всю команду целиком в терминал VPS. Она установит GitHub CLI из официального репозитория:
curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg | sudo dd of=/usr/share/keyrings/githubcli-archive-keyring.gpg && echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null && sudo apt update && sudo apt install gh -y
Дождитесь завершения — это займёт 30–60 секунд.

Шаг 3. Авторизовать GitHub CLI — подключаем токен, который создали на шаге 1.

Авторизовать GitHub CLI через токен
Замените <ВАШ_ТОКЕН> на токен, который скопировали (начинается с ghp_):
echo "<ВАШ_ТОКЕН>" | gh auth login --with-token
Если команда выполнилась без ошибок — авторизация успешна.
Проверить авторизацию GitHub CLI
gh auth status
Должно показать: ✓ Logged in to github.com account <ваш_username>
🔐 Безопасность токена: PAT даёт полный доступ ко всем вашим репозиториям. Не делитесь им ни с кем. Если подозреваете утечку — сразу отзовите токен: GitHub → Settings → Tokens → Revoke. Токен хранится на вашем VPS, который защищён паролем — это безопасно.
Часть 3: Тестируем всё вместе
Тест SSH: OpenClaw пушит файл в существующий репозиторий
Отправьте промпт ниже боту в Telegram (OpenClaw):
📋 Промпт: тест SSH (push в репо)
Склонируй мой репозиторий git@github.com:<ВАШ_USERNAME>/sites.git и создай в нём файл index.html с простой страницей «Привет, мир!», затем закоммить и запуш на GitHub.
✅ Если после push вы видите файл index.html в репозитории на GitHub — SSH работает!
Тест GitHub CLI: OpenClaw создаёт новый репозиторий
Отправьте промпт ниже боту в Telegram (OpenClaw):
📋 Промпт: тест GitHub CLI (создание репо)
Создай новый приватный репозиторий на GitHub с названием "test-openclaw", добавь в него файл README.md с текстом "Тестовый репозиторий от OpenClaw", закоммить и запуш. Используй команду gh repo create для создания репозитория.
🎉 Если на GitHub появился новый репозиторий test-openclaw с файлом README.md — полный доступ настроен! OpenClaw теперь может сам создавать репозитории, пушить файлы, управлять Pages — всё через Telegram.

Зачем это в будущем: когда вы создадите своего AI-агента (урок 6), его конфигурацию лучше хранить в отдельном репозитории на GitHub. Это бэкап: если OpenClaw что-то сломает в агенте — вы всегда можете откатить к рабочей версии. GitHub CLI позволяет OpenClaw самому создавать такие репозитории и поддерживать их актуальными.

Часть 4: GitHub MCP
🔌 Помните MCP из урока 3? Это «переходник», через который агент управляет внешним сервисом. Сейчас подключим официальный GitHub MCP — он даёт Claude Code и OpenClaw готовые структурные инструменты GitHub: issues, pull requests, ревью кода, поиск по репозиториям.

Три инструмента — три уровня, не дублируют друг друга:

— SSH-ключ → пуш, клон, коммит файлов в репозитории
— GitHub CLI (gh) → создание репозиториев и Pages из консоли сервера
— GitHub MCP → структурные инструменты GitHub (issues, PR, ревью, поиск) для Claude Code на компьютере и для агента OpenClaw

✨ Хорошая новость: GitHub MCP — это удалённый сервер от GitHub. Никакого Docker и установки не нужно, подключается одной командой.

Шаг 1. Подключить GitHub MCP в Claude Code (VS Code) — на вашем компьютере. Команда такая же по логике, как при подключении MCP в уроке 3.

Добавить GitHub MCP в Claude Code
Откройте терминал в VS Code и выполните (одинаково на Mac и Windows):
claude mcp add --transport http --scope user github https://api.githubcopilot.com/mcp/
--scope user — MCP будет доступен во всех ваших проектах на этом компьютере, а не только в одном.
Авторизоваться через GitHub
1. Запустите Claude Code (команда claude или чат в VS Code)
2. Введите /mcp
3. Выберите github → Authenticate
4. Откроется браузер → войдите в свой GitHub → подтвердите доступ. Готово — токен вводить не нужно.
Проверить подключение
claude mcp list
Должно показать ✓ Connected · github. Теперь Claude Code умеет работать с вашим GitHub структурно.

Шаг 2. Подключить GitHub MCP в OpenClaw — руками в терминал не лезем. Это делает ваш инженер — Claude Code. Он подключён к серверу ещё с урока 3 и знает OpenClaw по официальной документации (скилл openclaw-docs). Вы просто ставите задачу промптом.

Поручить Claude Code подключить GitHub MCP в OpenClaw
Отправьте промпт ниже в Claude Code. Подставьте тот же PAT, что создали в Части 2:
📋 Промпт: GitHub MCP в OpenClaw (через Claude Code)
Подключи официальный GitHub MCP к моему OpenClaw на сервере. Сначала сверься с документацией OpenClaw — открой скилл openclaw-docs, раздел про MCP (команда «openclaw mcp»). Подключись к серверу по SSH, как обычно. Параметры: эндпоинт https://api.githubcopilot.com/mcp/, транспорт streamable-http, авторизация заголовком «Authorization: Bearer <ВАШ_ТОКЕН>» (это мой PAT из Части 2). После установки проверь подключение и список инструментов, затем примени изменения, чтобы агент сразу их увидел. Если что-то пойдёт не так — остановись, объясни причину и почини сам.
🔐 Безопасность токена: это тот же PAT, что вы уже создали — отдельный заводить не нужно. Claude Code пропишет его в конфиг на вашем сервере; в логах OpenClaw токен маскируется. Если не хотите держать токен в конфиге — попросите Claude Code подключить через OAuth (вход в браузере) вместо заголовка.
🎉 GitHub MCP подключён в обоих контурах! Теперь и Claude Code на компьютере, и агент OpenClaw в Telegram умеют не только пушить файлы, но и создавать issues, открывать pull requests, ревьюить код и искать по репозиториям.

Покупка домена на Porkbun
🌐 Почему Porkbun: дешёвые домены, бесплатный WHOIS-прайваси (скрытие ваших данных), бесплатный SSL, удобный интерфейс.
Купить домен на Porkbun
Поиск → выбор зоны (.com — универсальный, .site — дешёвый, .dev — для техно) → оплата картой.
porkbun.com — купить домен
📎 Альтернативные регистраторы

Namecheap — namecheap.com — классика, бесплатный WHOIS-прайваси.

Reg.ru — reg.ru — для оплаты рублями, но дороже.

Настройка DNS для GitHub Pages

После покупки домена нужно указать, что он должен вести на серверы GitHub Pages. Это делается через DNS-записи в панели управления Porkbun.

Открыть управление DNS в Porkbun
1. Войдите в аккаунт Porkbun
2. Перейдите в Domain Management (управление доменами)
3. Найдите ваш домен → нажмите DNS (или иконку шестерёнки → DNS Records)
Вы окажетесь на странице, где можно добавлять и удалять DNS-записи.
porkbun.com/account — панель управления
Удалить стандартные записи Porkbun
На странице DNS вы увидите уже готовые записи (parking page от Porkbun). Удалите их все — они будут мешать. Нажмите иконку удаления (🗑️) рядом с каждой записью.

Теперь создаём новые записи. На той же странице DNS в Porkbun есть форма для добавления записей. Нужно создать 5 записей (4 типа A + 1 типа CNAME) — по одной за раз.

📌 Про IP-адреса в таблице ниже: это не ваши адреса. Это официальные фиксированные IP-адреса серверов GitHub Pages — одинаковые для всех пользователей GitHub в мире. Прописывайте их ровно как в таблице, ничего не меняйте. 4 адреса вместо одного — для надёжности: если один сервер упадёт, трафик пойдёт на другой.
💡 Что такое A-запись и CNAME — простым языком

A-запись (Address Record) — самая базовая DNS-запись. Она говорит интернету: «этот домен → вот этот IP-адрес». Когда кто-то вводит mybusiness.com, DNS смотрит A-записи и направляет браузер на сервер GitHub Pages. Мы создаём 4 штуки, потому что у GitHub 4 сервера — для отказоустойчивости.

CNAME (Canonical Name) — запись-алиас. Она говорит: «этот поддомен — то же самое, что вон тот адрес». Мы создаём CNAME для www, чтобы www.mybusiness.com тоже работал и вёл на ваш GitHub Pages. Без этой записи будет работать только mybusiness.com (без www).

Создать 4 A-записи
Для каждой A-записи: Type → A, Host → оставить пустым, Answer → IP-адрес из таблицы. Повторите 4 раза для каждого IP-адреса. Это адреса серверов GitHub Pages — они принимают трафик вашего домена.
Создать CNAME-запись для www
Type → CNAME, Host → www, Answer → username.github.io (замените username на ваш логин GitHub). Эта запись нужна, чтобы www.ваш-домен.com тоже работал.
⚠️ В CNAME-записи замените username на ваш реальный логин GitHub. Например, если ваш GitHub — ivanov, то Answer будет ivanov.github.io.
🔒 HTTPS: ничего покупать не нужно. GitHub Pages сам выпустит бесплатный сертификат Let's Encrypt после привязки домена в следующем блоке. Нужно только подождать пропагации DNS.
⏳ DNS-пропагация обычно занимает 5–30 минут, иногда до 24 часов. Если домен не заработал сразу — это нормально, ждём.

Подключение домена к GitHub Pages
Включить GitHub Pages в Public-репозитории
Репозиторий → Settings → Pages → Source: Deploy from a branch → Branch: main, папка: / (root) → Save
Привязать свой домен
В том же разделе Pages → Custom domain → вписать свой домен (например, mybusiness.com) → Save. GitHub создаст файл CNAME в репозитории автоматически.
Включить Enforce HTTPS
Поставить галочку Enforce HTTPS в настройках Pages. Если галочка неактивна — подождите, пока DNS пропагируется.

Откройте https://ваш-домен.com — должна отобразиться страница из репозитория.

Бонус: готовые дизайн-стили Refero
🎨 Refero Styles — библиотека из 2000+ дизайн-систем, снятых с топовых продуктов (Apple, Vercel, Linear, Resend и других). Каждый стиль — это готовый файл DESIGN.md с палитрой, типографикой, отступами и компонентами, который «понимает» Claude Code.

Как пользоваться — 3 шага:

1. Откройте styles.refero.design и найдите подходящий стиль (вкладки Trending / Popular / Newest или поиск).
2. Откройте карточку стиля и скопируйте его DESIGN.md.
3. Отдайте этот DESIGN.md агенту: «Сделай лендинг для … в стиле из этого DESIGN.md» — и вставьте текст. Агент применит палитру, шрифты и отступы из выбранного стиля.

🛡️ Безопасность скиллов: скиллы — это код от сообщества. Не все из них безопасны. Правила перед установкой любого нового скилла:

1. Читайте SKILL.md перед установкой. Если дизайн-скилл просит доступ к вещам, не связанным с его функцией (файловая система, отправка данных наружу) — это 🚩 красный флаг.

2. Проверяйте на ClawHub через VirusTotal. На странице скилла есть отчёт VirusTotal — автоматическая проверка на вредоносный код. Если помечено как risky — не ставьте.

3. Смотрите репутацию. Кто автор, сколько звёзд на GitHub, когда последний коммит. Скилл от anthropics (Anthropic) — безопасен. Скилл от анонима с 0 звёзд — сомнителен.

Наш frontend-design безопасен: официальный скилл от Anthropic (репозиторий anthropics/skills), генерирует только HTML/CSS. Это эталон надёжного источника.

Правило: если сомневаетесь — не ставьте. Лучше спросите в чате группы.
